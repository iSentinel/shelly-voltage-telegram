# Joined stop and rescue evidence rehearsal

The QA-only joined adapter validates the journal chain and binds the
stopped legacy container to the prior inhibition observation. It
requires matching Docker ID, old image, current stopped state, retired
selected editor, exact pending token and verified rescue parity.

After re-reading the observed state, compare-and-append checks that the
journal checksum has not changed under its local lock. The checksum is
a consistency mechanism, not an authentication signature or a lock
against external runtime changes.

The November 22 rehearsal starts with an actual verification of the
previously published 0.5.26-hw signed pair on Proxmox. The private journal
is transferred to the disconnected LXC114 and its bytes compared. The
run uses the existing signed 0.5.25-hw image with a dummy process, a
synthetic SQLite history, an isolated fence, and dummy systemd units.

An unretired editor must block the rescue observation; after the
selected owners are retired, the backup is verified twice. The chain
stops at review of strict-supervisor staging, not activation. The
fixture is then cleaned, so this historical journal is not resumable
as a live transaction. No receipt is fabricated or imported as trusted
authorization. Production remains untouched and its incident bridge
continues running.

A real staged signed receipt and positive strict boot, all-owner
inventory, durable operation orchestration and fresh owner approval
for the exact successor still remain required.
